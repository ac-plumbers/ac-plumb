    File: src/components/fundations/head/scripts/Schema.astro
          (check fundations/head/ if name differs)
--------------------------------------------------------------------------------

  Problem: Wrong @type, hardcoded dateModified, dangling breadcrumb
           reference, and text-format opening hours.

  Steps:
    1. Read Schema.astro fully before making any change.
    2. Make only these targeted changes — touch nothing else:

    a) Type specificity
         "@type": "LocalBusiness"  →  "@type": "Plumber"

    b) Dynamic dateModified
         Replace any hardcoded date string with:
           const today = new Date().toISOString().split('T')[0];
         Then reference it as: "dateModified": today

    c) Dangling #breadcrumb reference
         In the @graph array, if a node references:
           { "@id": "https://acplumb.co.uk/#breadcrumb" }
         without a full BreadcrumbList definition elsewhere in @graph,
         remove the dangling reference.
         Do NOT add a BreadcrumbList — that is out of scope here.

    d) #website node
         Verify a WebSite node with "@id": "https://acplumb.co.uk/#website"
         is fully defined in @graph (not just referenced). If it only
         appears as a pointer, add this minimal node:
           {
             "@type": "WebSite",
             "@id": "https://acplumb.co.uk/#website",
             "url": "https://acplumb.co.uk",
             "name": "AC Plumbers Ltd."
           }

    e) openingHoursSpecification — structured format
         Replace the text string with:
           "openingHoursSpecification": [
             {
               "@type": "OpeningHoursSpecification",
               "dayOfWeek": ["Monday","Tuesday","Wednesday","Thursday","Friday"],
               "opens": "08:00",
               "closes": "17:00"
             }
           ]
         Adjust hours if BUSINESS_CONFIG holds the actual values.

    3. Run: npm run build
    4. Validate at: https://search.google.com/test/rich-results
       Test the homepage and one /services/[slug] page — zero errors.

--------------------------------------------------------------------------------
[ ] TASK 4.1 — Add /_astro/* immutable cache rule                  Risk: Low
    File: netlify.toml
--------------------------------------------------------------------------------

  Problem: Existing cache headers cover /assets/* and /images/* but not
           /_astro/* where Astro puts its hashed build outputs.

  Steps:
    1. Read netlify.toml fully — note all existing [[headers]] blocks.
    2. Add this new block (do not replace or modify existing rules):

         [[headers]]
           for = "/_astro/*"
           [headers.values]
             Cache-Control = "public, max-age=31536000, immutable"

--------------------------------------------------------------------------------
[ ] TASK 4.2 — Add No-Vary-Search header                           Risk: Low
    File: netlify.toml
--------------------------------------------------------------------------------

  Problem: UTM query parameters are treated as separate cache entries,
           fragmenting cache hit rates.

  Steps:
    1. Read netlify.toml — check if a for = "/*" [[headers]] block exists.
    2a. If a for = "/*" block exists: add to its [headers.values]:
          No-Vary-Search = "params=(utm_source utm_medium utm_campaign utm_content utm_term)"
    2b. If no for = "/*" block exists: add:

          [[headers]]
            for = "/*"
            [headers.values]
              No-Vary-Search = "params=(utm_source utm_medium utm_campaign utm_content utm_term)"
